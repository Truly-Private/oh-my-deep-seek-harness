# Agent Note: 主机智能体扩展使用仅自动化 ACP 服务器

Status: implemented

[English](2026-08-15-host-agent-acp-bridges.md) | 中文

## 问题

Pi、Oh My Pi 与 Hermes 可以和 DeepSeek Harness 共享模型端点，但不会因此共享智能体生命周期语义。主机扩展必须保留 DSH 权限请求、取消、工作区限制、凭据处理、结构化结果与进程所有权，不能把端点兼容性或捕获的 CLI 输出当作智能体桥接。

## 决定

下游基于现有仅自动化 ACP 服务器提供候选主机原生适配器。Pi 与 OMP 使用独立 TypeScript 入口并共享一个拥有进程的 ACP 客户端；Hermes 使用通过 `plugin.yaml` 注册的 Python 标准库 ACP 客户端。每个模型可见工具只接受 `prompt`。启动器参数、规范工作区根目录、环境变量允许清单、权限预设与清理宽限时间都是不可变的部署配置。

语言无关的版本 1 结果区分 `completed`、`canceled`、`denied`、`failed` 与 `incompatible`，并提供稳定错误代码与清理状态。十四个 JSON fixture 命名所需的跨主机场景。无密钥测试运行脚本化 ACP 子进程，证明 UTF-8 结果、权限结果、协作式与强制取消清理、识别符号链接的工作区检查、环境变量过滤、协议失败与并发隔离。

Pi 与 OMP 通过各自主机确认界面显示 ACP 权限请求，并在没有界面时保持关闭。Hermes 0.16.0 插件处理函数既不公开交互式审批回调，也不公开中止信号，因此 Hermes 插件默认拒绝权限请求，并且在完整审批与主机取消语义方面仍不完整。集成状态参考按照[已审查下游接收策略](../process/2026-08-15-reviewed-downstream-intake.md)把这些路径标为候选，而不是完整桥接。

## 曾考虑的替代方案

- **封装 `dsh --profile headless` 并解析其输出**：捕获的标准输出无法保留 ACP 权限请求、取消确认或连接拥有的清理，因此拒绝。
- **使用当前 DSH JSON-RPC SDK**：其客户端约定缺少所需的轮次中取消与服务器到客户端权限请求路径，因此拒绝。
- **向所有主机公开一个 MCP 服务器**：已测试的 Pi 与 OMP 集成点是原生扩展；增加 MCP 会引入另一层转换，却不能证明等效权限与取消行为，因此推迟。
- **把 Hermes 权限请求视为自动允许**：Hermes 缺少交互回调是兼容性限制，不是授权，因此拒绝。

## 影响

这些适配器复用 DSH 现有会话与审批权威，并保持模型可调用配置足够窄。TypeScript 与 Python 都存在进程树和环境变量代码，因此共享 fixture 与主机特定测试必须持续发现语义漂移。Pi 与 OMP 可以加载候选扩展，Hermes 可以运行无需审批的 ACP 任务；在与提交匹配的真实主机证据覆盖每条所需生命周期路径之前，任何主机都不会获得完整集成标签。
