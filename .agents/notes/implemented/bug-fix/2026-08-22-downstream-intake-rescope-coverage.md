# Agent Note: Downstream intake rescope and coverage correction

Status: implemented

English | [中文](2026-08-22-downstream-intake-rescope-coverage.zh.md)

## Problem

The upstream intake rescope changed workspace packages to `@truly-private/omdsh-*`, but the dynamic client bundle purity gate and one credentials invariant assertion still selected `@deepseek-ai/*`. Undeclared downstream cross-plugin value imports therefore bypassed the build error, while the invariant test expected the wrong package identity. The intake adapter also changed several English expectations without changing fixtures that explicitly selected Chinese, so those tests contradicted their setup. The merge retained the downstream 9Router default selection but dropped the provider configuration that makes the selection executable. Under the complete Linux coverage workload, real PowerShell PTY and Loader-composition suites could miss persistent-shell output while they competed across the broad and process-bound test projects under aggregate instrumentation. Serializing those projects removed the overlap, but a hosted run still timed out while bootstrapping PowerShell because every process-bound suite reused one instrumented Vitest process after the PowerShell executor suite. Fresh-process isolation exposed a second hosted race: if the first readiness poll ran after the silence threshold, submitted PowerShell input could inherit the shell's proven pre-write stdin wait and settle `inferred_idle` before the shell consumed it. Blocking that silence path exposed the remaining ordering defect: a prompt marker emitted for the preceding send could arrive after the next provider write and be mistaken for current completion. The local node-pty provider also forwarded PowerShell's cursor-position query without answering it. The bootstrap could therefore reach PSReadLine before its native prompt accepted input, while a substring readiness check could mistake the echoed bootstrap source for the installed prompt because that source contains the prompt literal.

The six-worker Web snapshot job exposed independent timing and artifact-ownership defects. The HMR scenario restored dynamic plugin bundles but left `apps/web/dist` rewritten, invalidating the complete-build digest before the built-bundle smoke loaded. Theme checks observed the persisted file before the Host settings write committed in memory and still intercepted the upstream bundle route after the downstream rescope. Reference and Markdown-image snapshots could capture before the saved `trifecta` selection arrived, the subagent hover catalog could be queried before it mounted, and the two-message steering fixture allowed too little streaming time for three browser gestures under concurrent CI load. A cold seeded-history page could render its persisted transcript before the resumed host agent attached, so a direct live-event append failed under the same load. The DeepSeek comment-liveness snapshot used a 150-millisecond idle watchdog with ten-millisecond heartbeats, which left too little event-loop scheduling margin in the concurrent snapshot pool and could produce an unintended retry. The keyless Web retry smoke also capped the whole real-host lifecycle at 30 seconds even though its own boot and recovery waits had explicit longer bounds.

Other release-shaped checks depended on incidental scheduler timing. The history-and-streaming scenario could consume its finite replay before establishing the reader anchor, transcript capture could retain the off-bottom control after the answered question settled, and responsive queue geometry was measured before the browser completed layout after a viewport change. The live workflow fixture could settle while Playwright stabilized its child-navigation button after the test completed the required disclosure and responsive-layout checks. The subagent catalog test dispatched resize without proving that the open-menu effect had installed its listener. A process-heavy Oxlint retry retained the five-second default test timeout. PowerShell scrollback can terminate a prompt with LF or CRLF, but both prompt-installation loops accepted only the bare prompt in scrollback and could wait indefinitely after the shell was ready. The real persistent-PowerShell Loader test also ignored the state-initialization result and gave the tool only twenty seconds under full instrumentation, so a genuine command timeout reset the shell and appeared later as lost state.

## Decision

The client purity gate treats `@truly-private/*` as the owned workspace scope, retains explicit inline allowances for `@truly-private/omdsh-*` wire packages and generated Remote contributions, and allows the separately vendored `@deepseek-ai` libraries before applying the downstream scope check.

The official client build profile embeds `oh-my-deepseek-harness` as the product title. Release-shaped artifacts therefore use the downstream identity without changing the explicit upstream credits.

The credentials invariant test expects the downstream package identity. The base bundle restores the first-party 9Router provider with the credential reference, loopback endpoint, OpenAI-compatible protocol, and the requested `trifecta` model; it does not embed a credential.

Locale tests assert the language each fixture selects. Fixtures that stage `zh` keep the shipped Chinese copy expectations and exercise an explicit switch to `en` where both dictionaries matter.

The real `pwsh-local` executor, `terminal-bash` local PTY, and persistent PowerShell Loader-composition suites remain in the existing process-bound Vitest project. Partitioned coverage runs only the thread-safe project in concurrent shards, waits for them all, runs the process-bound core once, then runs each real PowerShell or PTY suite in its own fresh single-worker Vitest process. It merges every coverage blob and enforces the same thresholds. Real process owners therefore remain instrumented without overlapping another coverage shard or inheriting process-global state from an earlier PowerShell suite.

The local node-pty provider answers complete or split `CSI 6 n` cursor-position queries with a minimal `CSI 1;1 R` response. PowerShell startup first waits for printable native-prompt output, submits the encoding and controlled-prompt bootstrap exactly once, and then accepts readiness only when the installed prompt is the viewport or scrollback suffix. The persistent PowerShell tool uses the same suffix requirement when installing its private prompt. Its assembled keyless snapshot records the exact `PWSH_OK` tool result without bootstrap source, clipping text, or credential material.

When pre-write inspection supplies foreground evidence, a send with submitted input cannot settle through silence until polling observes a foreground-group transition, departure from a proven stdin wait, or a successful interrupt. Silence inference measures a fresh `idleSilenceMs` window from the first observation of that post-write foreground activity rather than applying silence accumulated before a delayed poll. The known pre-write group, while it remains foreground and busy, cannot settle through silence; it must return to an accepted stdin wait, yield an exact prompt handoff, or reach the absolute timeout. A foreground group that was already busy before the write is not post-write activity; if it returns to stdin wait between polls, printable post-write output is required before that wait can settle the send. A prompt marker becomes current-send evidence only after the same foreground activity, earlier printable output, or printable text before that marker in the same callback. A delayed marker and prompt from the preceding send cannot complete its successor. `TerminalSendRequest.expectedPromptText` lets a consumer that owns a replacement prompt declare its exact printable value; the persistent PowerShell tool supplies its private prompt on initialization, commands, and polling sends. Tool-level command completion requires the current wrapper's unique end marker followed by a numeric status, whether that evidence comes from retained scrollback or incremental operation output. Poll-only sends and providers without foreground evidence retain the existing silence fallback.

The HMR scenario snapshots every artifact covered by the complete-build digest, stops both writers before restoration, replaces the generated Web tree, restores all original bytes, and revalidates the build record during teardown. Browser checks wait for the Host's authoritative theme and model state rather than file or first-paint proxies, including every golden that records the persisted `trifecta` selection; they intercept the downstream `@truly-private/omdsh-client-ui-theme` route and wait for the subagent catalog tree before selecting a row. The two-message steering scenario receives a dedicated replay pace sized for the six-worker pool; other steering scenarios retain their shorter pace. The seeded-history scenario waits for the authoritative host agent attachment before appending live context to a cold resumed session. The DeepSeek comment-liveness fixture sends 25-millisecond heartbeats for one second against a 500-millisecond idle watchdog, preserving a twentyfold per-heartbeat scheduling margin while still proving that comments keep a stream alive beyond the watchdog duration. The Web retry smoke retains its bounded 20-second recovery poll and uses the same 120-second outer lifecycle budget as the other real-host smoke.

The history-and-streaming scenario uses a dedicated 600-delta replay and asserts that streaming remains active before testing concurrent arrival. Answered-question capture returns to the transcript bottom, while queue and context-panel geometry polls the rendered invariant after responsive layout settles. The live workflow scenario uses a replay interval sized to preserve its child-navigation window while the six-worker browser pool completes the preceding disclosure and responsive-layout assertions. The subagent catalog test waits for the open-menu effect and proves resize-driven menu placement. The process-heavy Oxlint retry receives an explicit twenty-second test timeout.

Both PowerShell prompt-installation loops recognize the private prompt as a bare suffix or as a suffix followed by LF or CRLF. Regression fixtures prove newline-terminated scrollback readiness and distinguish a native-prompt success followed by a setup timeout. The real Loader composition requires an explicit state-ready result before checking persistence, gives PowerShell startup thirty seconds, and gives the instrumented command sixty seconds inside a 120-second test budget; a timeout therefore fails at initialization instead of masquerading as state loss.

## Alternatives considered

**Change the fixtures to English.** The affected client surfaces intentionally ship Chinese product copy, and the tests already state that they select Chinese. Changing the fixture would hide the intake mismatch instead of preserving the upstream behavior.

**Remove the purity assertions after rescoping.** That would permit a client plugin to inline a second workspace runtime or request a module-table row it never declared. The downstream scope needs the same enforcement the upstream scope had.

**Retry the PTY assertions or only lengthen their timeouts.** Either change would conceal loss of a persistent-shell boundary under aggregate contention or process-global contamination. The process-bound inventory and partition coordinator give each real PowerShell or PTY suite a fresh instrumented process.

**Increase the PowerShell silence threshold or accept a prompt after the current start marker.** Scheduler contention can exceed any chosen heuristic, so a longer threshold would only make the race less frequent. PSReadLine echoes the wrapper, including its start marker, before the shell executes it; a delayed prompt can follow that echo while the command is still pending. Requiring the unique end marker and numeric status attributes completion to the executed wrapper.

**Accept a prompt literal anywhere in captured output.** The submitted PowerShell function contains that literal before the function has executed. Only the final prompt suffix proves that the shell accepted the bootstrap and returned to its controlled input state.

**Ignore or retry the Web snapshot failures.** The build-record rejection identified a real shared-artifact mutation, while the browser failures showed missing synchronization against authoritative state. Retries would make publication evidence depend on scheduler luck.

## Consequences

Downstream browser builds again reject undeclared workspace value imports, while vendored framework libraries remain usable. The package identity assertions and locale fixtures agree with the downstream runtime, the base profile can resolve its selected 9Router route, the complete coverage gate isolates each real PowerShell or PTY lifecycle without removing it from coverage, and the Web snapshot pool preserves the client artifact digest while waiting for durable UI state. Responsive, retry, comment-liveness, and streaming checks preserve their behavioral assertions under the release worker pool, newline-terminated PowerShell prompts no longer strand shell creation, and scheduler delay cannot complete provider-proven unconsumed input through silence or a preceding send's delayed prompt. A clean network-disabled native ARM64 Ubuntu OrbStack container, using Proto-provisioned runtimes and an unprivileged test user, passed the instrumented persistent-loader test and all eight local terminal lifecycle tests. The complete keyless snapshot suite passed 127 tests with two expected skips. These corrections do not promote the upstream intake beyond `candidate` or authorize a release.
