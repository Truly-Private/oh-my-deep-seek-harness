# Agent Note: 全新容器中的智能体对比保留可执行证据

Status: implemented

[English](2026-08-19-fresh-container-agent-comparison.md) | 中文

## Problem

比较使用和不使用下游 Harness 的 Pi 时，不同提示词、模型、预装依赖、宿主凭据、外层智能体模型调用或主观截图都容易扭曲结果。生成的浏览器应用还需要可执行证据：只查看源代码无法证明生产构建成功、服务可以启动或所需游戏界面确实存在。

## Decision

对比测试台在两个独立的一次性 Linux 容器中运行 Pi 基线和 Pi 加 DeepSeek Harness；两个容器从同一个摘要锁定的基础镜像构建。所有语言运行时都由 Moonrepo proto 安装。两条路径使用相同的 Pi 版本、9Router `trifecta` 路由、提示词字节、空工作区、资源限制和具名 9Router 网关密钥变量。测试台不使用 DeepSeek 服务商密钥。基线路径提供 Pi 的常规编码工具。Harness 路径加载真实 Pi 扩展并直接调用 `dsh_delegate`，从而避免无关的外层 Pi 模型调用，同时保留已交付的宿主到 ACP 路径。

智能体阶段允许联网，因为模型调用和应用依赖安装需要网络。Docker 上下文会排除常见的本地环境文件和凭据文件。每个容器通过 Docker 宿主网关访问宿主上的 9Router 实例，只挂载输出工作区，不传递宿主凭据路径或 Docker socket，并在生成代码所执行的命令启动前删除 `NINE_ROUTER_API_KEY`。基线路径的模型运行时在内存中保留密钥。Harness ACP 运行时从位于工作区和 shell 沙箱之外的临时目录读取权限为 0600 的凭据文件，其子进程环境不含密钥。测试台会记录提交、工作树状态、版本、提示词哈希、运行顺序、耗时和生成文件哈希；清单会排除依赖目录和 Playwright 浏览器缓存，因为它们属于执行工具。独立的无凭据评估器离线运行，根文件系统只读。它运行可用测试，要求生产构建和本地服务成功，检查稳定的界面标记，并生成确定性的桌面端和移动端截图。

此方法生成可比较的工件，而不会自动判定胜者。单次运行无法控制服务商负载或模型非确定性；直接 Harness 路径报告桥接生命周期数据，而不是 Pi token 统计。维护者会重复试验，并综合解读功能、视觉和可维护性证据。测试台通过不会改变下游审核状态，也不会改变宿主桥接的候选标签。

此测试决策补充[宿主智能体 ACP 桥接决策](../architecture/2026-08-15-host-agent-acp-bridges.md)。后者继续保持活跃，因为其生命周期、权限、取消和兼容性依据并未被此测试台取代。

## Alternatives considered

- **在同一容器中运行两个智能体** — 不采用，因为共享缓存、已安装软件包和文件系统残留会使路径来源变得含糊。
- **让 Pi 通过提示词决定是否委派** — 不采用，因为 Harness 路径会增加一次外层模型调用、可变的工具选择和与下游智能体实现质量无关的额外成本。
- **挂载操作者主目录或现有登录文件** — 不采用，因为这会扩大秘密暴露范围，并使运行依赖未记录的宿主状态。
- **只评审源文件或一张截图** — 不采用，因为两者都无法证明安装和构建行为、响应式渲染、稳定评估标记或正在运行的应用。
- **计算单一汇总胜者分数** — 不采用，因为任意权重会掩盖有意义的权衡，并夸大小型非确定性样本的统计价值。

## Consequences

与原地对比相比，测试台需要更多时间和镜像存储，真实运行也会消耗模型 token。生成的项目必须使用文档规定的 npm 命令和界面标记，才能获得完整截图证据。作为回报，每个结果都关联到精确的提示词、依赖、容器、提交、构建和视觉工件；凭据传输保持最小范围；评审者也能区分损坏的交付物与风格偏好，而不会把一次运行当作发布或安全结论。
